# 07 · 基础知识与合规指南

> 跨境清关不是"填填表格发出去"就完事——理解核心术语、四大风控红线、EORI 信用体系，能帮你从根本上避开大部分风险。

## 关键术语速查

| 术语 | 全称 | 含义 |
|---|---|---|
| **欧盟区** | European Union | 27 国政治经济联盟，商品自由流动（需已清关） |
| **欧元区** | Eurozone | 20 国统一货币，结算注意汇率风险 |
| **T1** | T1 Transit | 未完税过境运输，货物在海关监管下跨境 |
| **T2** | T2 Free Circulation | 已清关自由流通，可在欧盟全境自由销售 |
| **MRN** | Master Reference Number | 18 位海关唯一编号——货物在欧盟的"海关身份证" |
| **Duty (A00)** | Import Duty | 进口关税，必须缴纳，**不能递延** |
| **VAT (B00)** | Value-Added Tax | 进口增值税，**可递延**至销售后申报 |
| **EORI** | Economic Operator Registration & Identification | 欧盟经济经营者注册识别号，全欧盟通用，清关必备 |
| **欧代** | EU Authorized Representative | 欧盟授权代表，商品入欧的"合规身份证" |
| **CBAM** | Carbon Border Adjustment Mechanism | 碳边境调节机制，欧盟的碳关税 |
| **MTC** | Mandatory Tariff Certificate | 钢铁制品的强制关税证书 |
| **ICS2** | Import Control System 2 | 欧盟进口控制系统第 2 版 |
| **Article 23** | EU VAT Directive Article 23 | 欧盟 VAT 指令第 23 条——递延申报资质的法律依据 |

## 四大海关查验风控红线

> 欧盟海关已进行数字化转型，查验转为基于**智能风控系统**的精准打击。理解这四条红线 = 理解海关系统在看什么。

### 🔴 红线一：价格逻辑

**系统自动比对**申报单价与同类产品历史平均价。低于数据库平均价即触发预警。

- ✅ 申报单价 = 合理市场价（高于数据库平均价或在合理区间）
- ❌ 申报单价 < 数据库平均价 → 系统标记"低报嫌疑"

### 🔴 红线二：归类逻辑

HS Code 决定关税税率和监管条件。**按大类匹配、高税率产品归入低税率编码**属于非合规行为。

- ✅ HS 编码 = 产品实际属性的小类编码
- ❌ HS 编码 = 大类（模糊）或低税率编码（非合规归类）→ 触发归类争议

### 🔴 红线三：数据逻辑

**系统交叉比对**重量、数量、品名。申报重量与单品重量 × 数量不符即触发矛盾警报。

- ✅ 毛重 = 单品净重 × 数量 + 包装重量（一致）
- ❌ 毛重 ≠ 单品净重 × 数量 → 系统标记"数据矛盾"

### 🔴 红线四：描述逻辑（ICS2 新规）

**系统识别敏感模糊词**。禁止使用"配件"、"零件"等笼统词汇。

- ✅ 品名 = 具体属性（如 "LED 灯泡，10W"）
- ❌ 品名 = 笼统描述（如 "灯具配件"）→ 触发描述模糊预警

## EORI 信用体系

每个进口商的 EORI 号都建立**独立信用档案**。低报、侵权、违禁品等违规行为会被记录：

- EORI 被标记为**高风险**后，所有后续货物查验率大幅提升
- 一个好的 EORI 可以在申报时获得更宽松的人工审核
- 跨境物流行业有共享的 EORI 风险黑名单

## 递延清关核心逻辑：Duty vs VAT

```
关税（Duty / A00）     VAT（增值税 / B00）
  ↓                     ↓
  "过路费"               "销售税"
  进口时必须支付         可递延至销售后申报
  不能递延               可以递延
  ↓                     ↓
  清关时必须立刻掏       销售后才掏
```

### 为什么选择递延

1. **资金效率提升**：仅缴纳关税，增值税递延，大幅降低资金占用
2. **合规性增强**：提供完整进口申报记录，保护电商平台账号
3. **清关独立性**：单票申报，不受其他货物影响

## 清关行接受 HS 编码争议 ≠ 他们会改数据库

很多人以为"清关行接受了我的争议 = 他们会改自己的数据库"。实际上：

- 好的清关行 → 接受合理争议 → 更新自己的申报数据库 → 下次同品类货物不会再用错误编码
- 差的清关行 → 接受争议只是这一票 → 不改数据库 → 下次你提同类货物还是同样的问题

**怎么判断清关行好不好：** 提过几次争议后，下次是否还需要提？如果每次都不需要了 → 他们真的在更新数据库。如果每次都要提 → 他们只是应付。

## 查验率 vs 查验质量

很多人以为"查验率低就是好事"。其实要分清楚：

| 情况 | 实际含义 |
|---|---|
| 低查验率 + 抽查快速放行 | ✅ 真的宽松 |
| 低查验率 + 查一票退一票 | ⚠️ 选择性严格——运气好没事，运气不好直接扣 |
| 高查验率 + 查完放得快 | ⚠️ 程序化检查——资料齐就没事 |
| 高查验率 + 查完长时间不处理 | ❌ 真的严格，避不开就只能等 |
